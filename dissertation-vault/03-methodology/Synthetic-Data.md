# Conduct Dataset

## Intro
The conduct-detection engine ([[ml-module]]) is trained and evaluated on a labelled dataset of
synthetic numerical features representing acceptable and toxic text/voice conduct. The current
experiment uses **no real messages, audio recordings, gameplay, public toxicity-corpus rows or
participant data**. The generator creates feature values and labels directly from controlled
distributions; it does not collect or transcribe chat.

This makes the pipeline reproducible and avoids processing real players' communications, but it
also limits what the results can show: they demonstrate model behaviour on the generator's
assumptions, not real-world detection accuracy.

## Ground-truth assumptions
- Acceptable conduct is represented by feature values that can include mild profanity, caps or
  fast/repeated messages, modelling the fact that competitive banter can share surface signals
  with abuse.
- Toxic conduct is represented by generated severity values `c ∈ [0,1]`, from borderline cases
  to unambiguous abuse. These are simulation parameters, not judgements about real messages.
- The generated signal combines severity, targeting and structural features; the experiment tests
  whether the models can distinguish the labelled classes under these programmed distributions.
- `text` and `voice` are synthetic channel labels. Voice rows use additional generated noise to
  represent a simplified channel difference; they are not transcripts, recordings or measured
  acoustic features.
- Labels (`acceptable` or `toxic`) are generated by the code from the simulation settings; no
  human annotators label real conduct.
- Class balance, severity distribution, channel mix, noise and random seed are documented in
  `generate_dataset.py`.

## Synthetic construction
The generator creates feature values for the following conceptual signals:

| Synthetic feature family | Role in the simulation |
|--------------------------|------------------------|
| Lexical proxies | Generated toxicity and severity scores |
| Targeting proxy | Generated indicator/score for targeted harassment |
| Structural proxies | Generated caps, repetition and message-burst scores |
| Channel metadata | `text` or `voice`; voice rows receive additional feature noise |

These are numerical proxies. No text is tokenised, no speech is transcribed, and no audio features
are extracted in the current experiment. Public datasets and authentic, consented game chat/voice
could be considered in future work only after appropriate licensing, ethics approval and data
protection review.

## Limitations
- The generator defines both the feature distributions and the labels, so the model may learn
  patterns specific to the simulation.
- Toxicity and acceptable banter are context-dependent; generated labels do not establish how
  people would judge real conduct.
- No real language, gaming slang, dialects, identity terms, speech or background noise are present.
  The current experiment therefore cannot measure bias or validate fairness across real groups.
- The voice channel is represented by metadata and added numerical noise, not by real speech or
  prosody.
- Results show technical feasibility under controlled synthetic conditions only. Validation on
  appropriately sourced, consented real-world data is future work.

## Implementation
Generator: `detection-engine/src/detection_engine/generate_dataset.py`. Feature names and channel
labels live in `constants.py` so dataset generation, training and the scoring API use the same
contract. The dataset is regenerated reproducibly from code and a fixed seed.

**Output:** `detection-engine/data/sample/conduct_dataset.csv` (synthetic feature values,
`offenceType` ∈ {`chatAbuse`,`voiceAbuse`,`none`}, `label`, `isToxic`, `channel`). The generated
dataset is git-ignored.
